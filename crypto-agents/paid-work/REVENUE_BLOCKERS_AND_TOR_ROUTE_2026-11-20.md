**Checked:** 20 November 2026, 02:09–02:20 Africa/Kampala. **Scope:** Existing verified GitHub Actions and public official publisher guidance; this is NOT a live on-chain payment claim or proof that a particular payout provider's program is open.

## Executive finding

**Our largest blocker is the ABSENCE OF A CUSTOMER WHO HAS AGREED TO PAY, not the quantity of generated worker IDs.** A valid deposit needs a legitimate payer and an actual acceptance obligation, followed by the payer's signed transfer. Neither code execution, new public posts nor simulated wallet requests can cause someone else to send BTC or USDC.

## Why adding the darknet does not manufacture coins

The Tor Project confirms that .onion addresses are Tor-only, privacy-oriented services: https://support.torproject.org/tor-browser/features/onion-services/ . This GitHub/public-web deployment cannot independently browse or host a verifiably reachable onion service. We will not enumerate unknown hidden markets, buy credentials or promise earnings from anonymous offers with no identifiable payer.

**Potential legitimate onion-adjacent paid lane:** Tor has historically maintained an official HackerOne software vulnerability reward program (historical Tor announcement: https://blog.torproject.org/we-will-pay-you-to-hack-tor-bug-bounty/ ). An actual reward requires a NEW, valid, in-scope security finding, authorized research, account verification and a formal award. **Program's present eligibility and bounty budget are not proven by that historical announcement.** HackerOne's Oct 2026 payout rules support BTC and USDC (minimum $15); Crypto USDC goes on **Ethereum ERC-20, not Base**. BTC payout supports BECH32. Account ID verification, tax document and payout setup are mandatory; reward collection triggers email to the owner (no email access is delegated to our agents). See https://docs.hackerone.com/en/articles/8395720-payment-preferences and https://docs.hackerone.com/en/articles/8399430-id-verification. This is a high-skill long-shot, not the fastest way to first BTC.

## One concrete 72-hour conversion strategy

1. **STOP treating processes or raw leads as revenue.** Each shift, select at most ONE newly independently verified global, no-fee, reasonable-scope buyer assignment with explicit payout and permitted authenticated submission. Skip stale, region-barred, fake-token-testnet, "buy worker plan", zero-funded or asset/network-mismatched tasks.
2. **First priority:** obtain an interested buyer for an existing proven $5 CSV cleanup or one small $15 BTC software QA/reconciliation service. Require public non-sensitive scope, exact acceptance test, amount and a compatible payment agreement. Buyer-facing service exists; zero unsolicited outreach; respond only via the owner's authorized public channels or genuinely permitted opt-in boards.
3. **Next priority:** use owner's authentic signed-in source-specific account to submit one original completed, newly qualified bounty entry. No upstream posting via a GitHub App lacking permissions. No automatic wallet signatures or unauthorized email/account creation.
4. **Payout contract:** one approved target BTC-mainnet address or a user-verified native Base USDC address, with **the payer confirming exact network and token**. If the platform only pays Ethereum USDC, don't assume the owner-approved Base address is sufficient; obtain new owner approval for the rail. Verify transaction and payer/invoice linkage before marking paid.
5. **Reality check:** track numbers daily as [independently funded tasks, permitted submissions, paid contract acceptances, completed accepted deliverables, confirmed BTC/USDC TXIDs]. Increase real workers only when one of those numbers rises and a new genuine source demands work. Only hardware owners can opt into real mining, with separate authorization and payout agreements.

## Present operating rules

NO email access, monitoring, drafting or sending by agents. NO personal data, private key custody, spending, miner hijacking, self-posting spam, fake buyer commitments, or "775 billion live" claims. Maintain hourly legitimate source checks, limit expensive model runs and retry only genuine new opportunities. **No money is earned merely by opening or preparing a bounty.**
