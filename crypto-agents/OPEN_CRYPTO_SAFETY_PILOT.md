# Open Crypto Receipts & Paid-Work Safety Kit — free public pilot

**Status: small open-source pilot, NOT a registered charity, NGO, incorporated nonprofit, approved grant recipient or confirmed fundraising campaign.**

## The problem

People and small online workers can be tricked by fake crypto bounties, fake mining yields, wrong-chain addresses, unsupported "payment received" claims and advance-fee requests. This project aims to share a no-cost, reproducible starter guide for checking crypto-paid work and transaction evidence.

## Public materials already available in this repository

- [Two-company public receiving-route checks](https://github.com/kwesigaamon8-web/Amon-Kwesiga/blob/main/crypto-agents/b_address_understanding.py): source code that distinguishes BTC mainnet from optional USDC Base routes and flags address confusion
- [Worker evidence audit](https://github.com/kwesigaamon8-web/Amon-Kwesiga/blob/main/crypto-agents/strict_worker_accountability.py): repeatable checks separating AI model replies and supporting sources from actual paid work
- [Read-only payment director logic](https://github.com/kwesigaamon8-web/Amon-Kwesiga/blob/main/crypto-agents/d10_payment_director.py): checks intended to keep unverified incoming transactions separate from verified customer payments
- [Original-source opportunity scout](https://github.com/kwesigaamon8-web/Amon-Kwesiga/blob/main/crypto-agents/new_earning_lanes.py): rules to reject obvious prepayment/credential requests and flag unverified rewards

These links show software experiments and research tools, NOT proven deployed services, audited code, public-benefit impact or an approved grant. Source code must be independently checked before anyone relies on it.

## Proposed first public deliverables (not yet funded or completed)

1. A free, plain-language guide covering Bitcoin mainnet receiving addresses, the difference between native BTC and USDC on Base, and when an exchange deposit memo/tag is needed.
2. A worked **fictional** example ledger showing a TXID, receiving output, asset, chain, amount, confirmation status and correct classification as gift, payment, self-transfer or unknown.
3. An original-source checklist for finding paid crypto bounties, verifying a real sponsor, avoiding fees, securing agreed terms and submitting work that can be accepted.
4. A zero-cost open GitHub feedback channel for corrections and usability issues, with no private keys or sensitive transactions collected.
