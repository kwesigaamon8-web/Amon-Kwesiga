# B1/B2 Independent Superworker Protocol (design, not activation evidence)

Owner objective: autonomous, cooperating assistants doing legitimate no-fee work to generate verified crypto income. Chief D coordinates B1 and B2. The 750,377,265,361 positions are a *logical role capacity*, not running processes.

## Minimum independently running worker
A worker counts as ACTIVE only if there is a real model invocation or running process, unique worker_id, task_id, provider/runtime, UTC start and end or heartbeat, input/output evidence location, and status. A role definition, prompt, GitHub matrix placeholder, simulated response or hash calculation is NOT an active worker. Concurrent count is unique workers with overlapping authenticated execution intervals or fresh heartbeats, not cumulative launches.

## Shared coordination
Each worker claims one task from a durable queue, researches independently within permissions, produces a useful artifact with citations/provenance, and submits for peer review. A separate reviewer checks originality, feasibility, compliance and duplicate work. B1/B2 directors route accepted deliverables; Chief D consolidates verified results and blockers. Tasks have idempotency keys, leases, retry ceilings and rate limits to avoid spam and runaway loops.

## Safe execution boundaries
No paid hosting, subscription, authentication, credential disclosure, new wallet route, material contract, signing, transfer or personal-data exposure without explicit owner approval. No unauthorized access, unsolicited mass messaging, scraping contrary to site terms, or GitHub/cloud mining. Use only permitted free compute and official APIs within quotas. Never claim billions of instances are active without proof.

## Payment and work ledger
For each accepted opportunity track source, buyer, task, evidence, submission, buyer acceptance, invoice/payment claim and actual confirmed payment as separate statuses. For self-custody payment verify chain, owner address, authentic asset contract/mint, txid and output index/log index, finality and amount. For custodial exchanges, authenticated account credit is required. API failures are UNKNOWN, not zero. Report native coin units, with BTC target as a separate metric.

## Deployment phases
1. Inventory existing workflows and actually connected runtimes.
2. Pilot two independently invoked workers and one reviewer; record execution logs.
3. Add persistent queue, budget and rate-limit controls; verify real concurrency.
4. Scale only to capacity allowed by real compute/model accounts and owner approvals.
5. Publish dashboard: roles configured, workers actually invoked, concurrent active, completed reviewed tasks, accepted paid work, verified receipts.

## Acceptance test
A worker is independently verified only when an auditor can retrieve its actual invocation record and distinct output. Report UNKNOWN for counts lacking records. Never manufacture evidence or claim a successful deployment merely because this protocol file exists.
